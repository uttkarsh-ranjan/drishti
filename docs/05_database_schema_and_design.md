# Database Schema & Design

## 1. Overview
The database layer needs to handle relational data (users, roles, compliance documents, inspection logs) as well as spatial data for strict geo-fencing requirements. 

## 2. Technology Stack
- **Database Engine**: PostgreSQL 15
- **Spatial Extension**: PostGIS

## 3. Core Schema Design (High-Level)

### 3.1. Users and Roles
- **`Users` Table**: Stores credentials (hashed passwords), names, and contact info.
- **`Roles` Table**: Defines permissions (DoSJE Official, PMU Inspector, NGO Admin).
- **`User_Roles` Table**: Mapping table for RBAC.

### 3.2. Institutions (NGOs)
- **`Institutions` Table**: 
  - `id`, `name`, `registration_number`, `status`.
  - `location`: A PostGIS `GEOMETRY(Point, 4326)` column storing the verified centroid GPS coordinate of the facility.
  - `rtsp_url`: Registered camera feed URL.

### 3.3. Assignments and Inspections
- **`Assignments` Table**: Generated by the WCSP engine.
  - `inspector_id`, `institution_id`, `scheduled_time`, `status` (Pending, Completed, Missed).
- **`Inspection_Logs` Table**: Immutable audit trail of the actual inspection.
  - `assignment_id`, `capture_time`, `inspector_gps` (PostGIS Point).
  - `distance_from_centroid`: Calculated during ingestion.
  - `evidence_hash`: SHA-256 hash of the submitted payload.
  - `status`: Accepted, Rejected (Geofence violation, Timestamp violation).

### 3.4. Evidence and AI Analytics
- **`Evidence_Files` Table**: Pointers to the Object Store where images/videos are saved.
- **`Anomalies` Table**: Output from the Celery workers.
  - `evidence_id`, `anomaly_type` (Crowd, Proxy), `risk_score` (0.0 to 1.0).
  - `shap_explanation`: JSON field storing the feature contributions for the explainable AI dashboard.
  - `reviewer_action`: Tracks human review outcomes (e.g., Validated, False Positive).

## 4. Implementation Details
- **Spatial Queries**: Use PostGIS functions like `ST_DistanceSphere` or `ST_DWithin` in combination with the backend logic to enforce the 200m geofence (Haversine calculation).
- **Immutability**: Audit logs and evidence records are append-only. Updates to critical compliance status are tracked in separate historical tables.
